# Дизайн оболочки

Здесь лежит то, как BetterDesk выглядит: токены и макет.

| Файл | Что это |
|---|---|
| `tokens.css` | **Единственное место, где живут цвета**, радиусы, отступы, шрифт, время анимаций |
| `mockup.html` | Статический макет главного экрана. Открывается двойным щелчком, без сборки |

Работающая оболочка — в `ui/`. Собирается в `.exe`:

```powershell
cargo run --release -p bd-shell
```

---

## Тема одна — светлая

Тёмной темы нет, и это **решение, а не упущение** (2026-08-31).

§6.2 задаёт «светлую, минималистичную, спокойную тему». Раздвоение
на две палитры означало бы, что каждый экран надо проверять дважды,
а каждый новый цвет заводить парой — при том, что вторая половина
работы никому пока не нужна.

Токены при этом остаются обязательными. Они нужны **не ради тёмной
темы**, а ради того, чтобы цвет вообще имел одно место жительства.
Если тёмная тема когда-нибудь понадобится, она добавляется в
`tokens.css` одним блоком, и ни один компонент не меняется.

Отдельно: `color-scheme: light` задана явно. Без неё тёмная тема
Windows перекрашивает поля ввода и полосы прокрутки внутри webview,
и светлый экран получает тёмные вставки.

---

## Правило пользования

**Компонент никогда не пишет литеральный цвет.** Только
`var(--accent)`, `var(--text-muted)` и так далее. Понадобился цвет,
которого нет, — сначала заводится токен, потом используется.

Копия `tokens.css` лежит в `ui/src/` — webview не может читать файлы
выше своего корня. Эта копия **производная**: её кладёт туда
`ui/src-tauri/build.rs` при каждой сборке. Правится только оригинал
здесь; правка копии будет молча затёрта.

## Решения, которые стоит понимать до правок

**Акцент один на экран.** Синий `--accent` стоит ровно на главном
действии — «Подключиться». Как только акцентом покрашено второе
действие, главного на экране не остаётся.

**Зелёный и оранжевый — не акценты.** Они сообщают *состояние*
машины (готов принимать, только просмотр), а не предлагают действие.
Зелёная кнопка рядом с синей заставила бы человека выбирать между
двумя «главными».

**Незавершённость помечается в интерфейсе, а не умалчивается.**
Жёлтая полоса «соединение по ID появится вместе с сервером связи —
этап 4» и кнопка, которая честно `disabled`. Показать рабочую с виду
кнопку, которая ничего не делает, — значит соврать: человек решит,
что сломалось у него.

По той же причине список сохранённых машин **пуст**, а не заполнен
красивыми выдуманными строками. Выдуманный список в макете —
иллюстрация; в работающей программе он был бы обманом.

**Состояние «ключ сменился» нарисовано в макете заранее.** §7.3
требует громкого предупреждения при смене ключа хоста — это защита
от MITM на сигналинге. Такое состояние должно существовать до того,
как впервые случится у живого человека.

**Окна сессии здесь нет, и не будет.** Видео не рендерится в webview
(§6.1): оно живёт в отдельном нативном окне с D3D11-swapchain, а
оверлей поверх него рисуется тем же Direct2D. Нарисовать сессию
«страницей» значило бы заложить в дизайн ровно ту архитектуру,
которую проект отвергает, — с композитингом браузера и лишними
10–20 мс.

## Две ловушки, которые уже сработали

Обе дали **неверную картинку без единой ошибки в консоли** — то
есть ровно тот класс дефектов, который ловится только глазом
(находка 36).

**`[hidden]` не работает без `display: none !important`.** Атрибут
скрывает только элементы с `display` по умолчанию; у всего, чему
задан `inline-flex`, `grid` или `block`, он молча игнорируется.
Значки «Готов принимать» и «Только просмотр» показывались
одновременно, и оранжевый перекрывал зелёный — экран сообщал прямо
противоположное правде о машине.

**Мост Tauri берётся внутри `try`, а не строкой выше.**
`window.__TAURI__.core` кидает при разборе скрипта — до того, как
появится хоть один обработчик, — и экран навсегда остаётся с
прочерками, ничего не сообщая. Обработка ошибки бесполезна, если
она недостижима из места, где ошибка возникает.
