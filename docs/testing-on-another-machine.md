# Проверка на второй машине

Инструкция для второй стороны. Читать код не нужно.

Цель — проверить то, что нельзя проверить на одной машине.

**Что уже подтверждено** прогоном Москва — Франция 2026-09-01:
соединение через интернет по девяти цифрам, обе стороны за
домашними роутерами, 1589 кадров, ноль потерь, RTT 68.6 мс.

**Что проверяется сейчас** (сентябрь 2026) — опознание машины по
ключу и пароль сессии на живом канале. Это новое: в прошлый прогон
их либо не было, либо они работали иначе. Подробности — в шаге 4,
раздел про отпечаток.

Отдельно полезен прогон **в локальной сети** (два компьютера у
одного роутера): там нет задержки интернета, и видно чистую цену
пайплайна.

**Чего этот прогон НЕ даст:** честной цифры задержки через
интернет. Способ, которым программа её меряет, через интернет
показывает не задержку, а её разброс — цифра в отчёте будет
заниженной, и клиент об этом сам предупредит. Настоящее измерение
требует съёмки двух экранов камерой, это отдельная работа.

---

## Про две стороны — прочитать первым делом

Роли **не симметричны**, и это важно понимать до начала:

| Роль | Что делает | Что для этого нужно |
|---|---|---|
| **Клиент** | смотрит чужой экран | декодер (есть почти в любой Windows) |
| **Хост** | отдаёт свой экран | захват **и аппаратный энкодер** |

Видеокарта NVIDIA для роли хоста **не обязательна**: поддерживаются
NVENC (NVIDIA), Intel QuickSync и AMD — всё, что Windows считает
аппаратным энкодером H.264. Обычно это есть на любой машине не
старше десяти лет, включая ноутбуки со встроенной графикой.

Чего пока нет — софтверного кодирования. Машина совсем без
аппаратного энкодера хостом быть не сможет; клиентом — сможет.
Шаг 2 покажет, какой случай перед вами.

---

## Что понадобится

- Windows 10 (сборка 1903+) или Windows 11, 64 бита
- [Rust](https://rustup.rs/) — при установке выбрать вариант по
  умолчанию (MSVC)
- Visual Studio Build Tools с компонентом «Разработка классических
  приложений на C++»

Для роли **клиента** видеокарта NVIDIA не нужна вовсе.

**LLVM ставить не надо.** Он нужен только для сборки NVENC-бэкенда,
то есть только хосту с картой NVIDIA. Без него сборка не падает:
в выводе появится строка `NVENC-бэкенд отключён`, и это нормально.

Если Build Tools не установлены, сборка остановится с сообщением
`linker link.exe not found`. Оно означает ровно одно: при установке
Build Tools не отмечена галочка «Разработка классических приложений
на C++». Отметить её и **перезагрузиться** — без перезагрузки система
не увидит новые программы. VS Code не подходит, это другая программа.

---

## Шаг 1. Собрать

```powershell
cargo build --release
```

Первая сборка занимает несколько минут. Если она падает — прислать
разработчику весь вывод целиком, дальше идти не нужно.

Собираются два приложения: `bd-host` (отдаёт экран) и `bd-client`
(смотрит), плюс набор проб для диагностики.

---

## Шаг 2. Проверить машину

**Это главный шаг.** Проба ничего не ломает и не требует соединения —
она только смотрит, что на машине есть:

```powershell
cargo run --release -p bd-bench --bin machine_probe
```

Вывод на машине без NVIDIA выглядит примерно так:

```
=== BetterDesk: проверка машины ===

✅ Захват экрана: DXGI Desktop Duplication работает, кодируется 1920x1080
     монитор 0: \\.\DISPLAY1 — 1920x1080
✅ Энкодер: Media Foundation: Intel® Quick Sync Video H.264 Encoder MFT
     (NVENC недоступен, и это нормально: ...)
✅ Декодер: H.264 D3D11VA готов (встроенный декодер Windows)

Энкодеры H.264, заявленные системой:
  • Intel® Quick Sync Video H.264 Encoder MFT — аппаратный
  • H264 Encoder MFT — софтверный

--- Вывод ---
✅ ХОСТ: машина может отдавать свой экран.
✅ КЛИЕНТ: машина может смотреть чужой экран.
```

**Прислать этот вывод целиком** — по нему видно всё нужное.

Как читать:

- **`✅ ХОСТ` и `✅ КЛИЕНТ`** — можно проверять в обе стороны.
- Строка «NVENC недоступен, и это нормально» — не ошибка: на машине
  без NVIDIA используется Intel или AMD, и это штатный путь.
- **`❌ ХОСТ`** — аппаратного энкодера нет вовсе либо ни один не
  подошёл. Клиентом машина при этом обычно остаётся годной.
- **`❌ КЛИЕНТ`** — дальше идти нельзя, нужен софтверный декодер,
  которого пока нет.

---

## Шаг 3. Открыть порты

Нужен **один порт**: 7000. Видео, ввод и курсор идут по нему вместе.

(Раньше портов было три — 7000, 7001, 7002. Отсюда старый симптом
«картинка идёт, а мышь и клавиатура нет»: открывали только первый.
Теперь такого не бывает — либо работает всё, либо ничего.)

На **хосте**, в PowerShell от администратора:

```powershell
New-NetFirewallRule -DisplayName "BetterDesk" -Direction Inbound `
  -Protocol UDP -LocalPort 7000 -Action Allow
```

Протокол именно **UDP**: QUIC работает поверх него, а не поверх TCP.

**Пробрасывать порт на роутере НЕ нужно** — ни в локальной сети, ни
через интернет. При подключении по девяти цифрам стороны
пробивают путь друг к другу сами; ради этого и заведён сервер,
который их сводит. Проброс понадобился бы только для подключения по
адресу (`--connect`) через интернет — а это запасной способ.

Правило файрвола Windows выше всё равно нужно: оно про сам
компьютер, а не про роутер.

Убрать правило после проверки:

```powershell
Remove-NetFirewallRule -DisplayName "BetterDesk"
```

---

## Шаг 4. Подключиться

**Адрес больше не нужен.** Хост печатает девять цифр, клиент вводит
только их — остальное стороны выясняют сами через сервер.

Тот, чей экран показывают (**хост**), запускает у себя:

```powershell
cargo run --release -p bd-host
```

Он напечатает три вещи, и **все три нужно продиктовать**:

```
╭──────────────────────────────╮
│  ID этого компьютера         │
│        955 235 149           │
╰──────────────────────────────╯

╭──────────────────────────────╮
│  Пароль сессии               │
│            460925            │
╰──────────────────────────────╯

Отпечаток этой машины (сверить при первом подключении):
  CCFC 3D03 1633 89F9 04D2 A2E5 0BE5 4656
```

Тот, кто смотрит (**клиент**), вводит только девять цифр:

```powershell
cargo run --release -p bd-client -- --id 955235149
```

Клиент спросит пароль — ввести те шесть цифр, что продиктовал хост.

**Пароль новый при каждом запуске хоста.** Если хост перезапустили,
прежний не подойдёт.

Обе стороны ждут по 5 минут: и подключения, и ввода пароля. Времени
на «найти окно, продиктовать, набрать» достаточно — раньше здесь
была минута, и её не хватало (человек диктует голосом дольше, чем
кажется).

Откроется окно с экраном хоста. **F9** показывает и прячет панель со
статистикой: задержка, fps, RTT, потери.

### Про отпечаток — что это и когда сверять

При **первом** подключении к этой машине клиент напечатает:

```
Эта машина видится ВПЕРВЫЕ. Её отпечаток:
  CCFC 3D03 1633 89F9 04D2 A2E5 0BE5 4656
```

Эти буквы и цифры надо **сравнить с тем, что показал хост** — на
слух, тем же звонком, которым диктовался пароль. Совпали — всё в
порядке, дальше клиент запомнит машину и молча проверяет сам.

Зачем это нужно: сервер, который сводит стороны по девяти цифрам,
мы не считаем доверенным. Отпечаток — единственное, что нельзя
подделать, не имея доступа к самой машине.

**Если клиент вдруг закричал «КЛЮЧ ЭТОЙ МАШИНЫ ИЗМЕНИЛСЯ»** на
машине, к которой уже подключались, — это либо подмена, либо у
хоста переустановили систему. Отличить нельзя, поэтому подключение
останавливается и решает человек. В обычной проверке такого быть не
должно; если случилось — **прислать снимок экрана целиком**.

### Подтверждение подключения (по желанию)

Хост можно запустить так, чтобы он спрашивал разрешение перед тем,
как показать экран:

```powershell
cargo run --release -p bd-host -- --ask
```

Тогда после ввода пароля у хоста появится вопрос `Пустить? [y/n]`.
Ответ `y` пускает, `n` отклоняет, молчание дольше минуты — тоже
отказ. Это отдельная проверка, для замеров задержки флаг не нужен.

**Проверить стоит обе ветки.** При `n` клиент должен написать
«хозяин машины отклонил подключение» и закрыться — **не** открыть
пустое окно и не сказать, что пароль неверный. Если увидите что-то
другое, это дефект: прислать вывод обеих сторон.

### Если сервер недоступен

Остаётся прямой способ — по адресу, без всякого сервера. Работает
только в одной локальной сети:

```powershell
# хост
cargo run --release -p bd-host -- --no-signaling --seconds 180
# клиент (АДРЕС — локальный IP хоста, например 192.168.1.5)
cargo run --release -p bd-client -- --connect АДРЕС:7000 --seconds 150
```

Порт нужен **один** — 7000: видео, ввод и курсор идут вместе.
`--seconds` задаёт длительность прогона, после чего обе стороны сами
печатают итоги. Хосту давать с запасом, чтобы он не завершился
раньше клиента.

### Управление хостом — отдельно и осознанно

По умолчанию хост ввод клиента **принимает, но не применяет**: мышь
и клавиатура на нём не шевелятся. Чтобы клиент действительно управлял
хостом, хост запускается так:

```powershell
cargo run --release -p bd-host -- --inject-input
```

Флаг явный намеренно. Пароль сессии и опознание машины теперь есть,
но управление чужим компьютером — отдельное решение, и включаться
молча оно не должно. Не оставлять хост запущенным «на всякий
случай»: пока он работает, к нему можно подключиться, зная девять
цифр и пароль.

### Проверить в обе стороны

Это **два отдельных прогона**, а не один: одна сессия показывает
экран в одну сторону.

1. Первый прогон: хостом машина A, клиентом машина B.
2. Второй прогон: поменяться ролями — хостом B, клиентом A.

Второй прогон получится, если `machine_probe` на машине B сказал
`✅ ХОСТ`. Видеокарта NVIDIA для этого не нужна — годятся Intel
QuickSync и AMD.

## Что смотреть глазами

Цифры соберутся сами, а вот это увидит только человек:

1. **Картинка живая**, не замирает и не идёт рывками.
2. **Нет пикселизации** — картинка не грубеет крупными квадратами.
3. **Курсор** нормального размера, и над текстом видна буква «I»,
   а не квадрат и не пустое место.
4. **Ничего не падает** за всё время прогона.

Если что-то из этого не так — описать словами, что именно видно.
Это ценнее любых цифр: несколько дефектов подряд нашлись именно так,
и ни один из них не давал ни ошибки, ни неверного числа.

---

## Что прислать в конце

1. Вывод `machine_probe` целиком.
2. Итоговые отчёты **обеих** сторон — их печатают `bd-host` и
   `bd-client` при завершении. Цифры двух сторон должны сходиться
   между собой, и расхождение само по себе полезная находка.
3. **Совпал ли отпечаток**, который показал хост, с тем, что
   напечатал клиент. Это главное в текущей проверке.
4. Словами: как выглядело — плавно или рвано, что было не так.

**Отдельно ценно — второе подключение подряд.** Запустить хост и
клиент ещё раз, не удаляя ничего. Клиент должен напечатать
«Машина опознана по сохранённому ключу» и **не** спрашивать про
отпечаток второй раз. Если он снова говорит «видится ВПЕРВЫЕ» —
это дефект, и его надо прислать: значит, запоминание не работает.

Задержка через интернет будет заметно больше, чем в локальной сети,
и это ожидаемо: критерий проекта (≤ 35 мс) задан для LAN. Здесь
проверяется не он, а то, что всё вообще работает на другой машине.

## Если что-то пошло не так

Приложения объясняют ошибки словами, а не кодами. Самые вероятные:

| Что видно | Что это значит |
|---|---|
| `linker link.exe not found` | Не установлены Build Tools с галочкой «Разработка классических приложений на C++». Поставить и **перезагрузиться**. VS Code — другая программа, не подходит |
| `Unable to find libclang` | Старая версия кода. Обновиться (`git pull`): теперь сборка без LLVM не падает, NVENC просто отключается |
| `NVENC-бэкенд отключён` в выводе сборки | **Норма**, а не ошибка. Значит нет LLVM; клиенту NVENC не нужен |
| `Захват экрана недоступен` | Гибридная графика — известное ограничение DXGI, фоллбэк запланирован |
| `Аппаратный декодер H.264 недоступен` | Нужен софт-декодер, его пока нет |
| `NVENC недоступен` | Норма: используется Intel QuickSync или AMD |
| `ни один аппаратный энкодер не подошёл` | Гибридная графика: энкодер не видит GPU, которому принадлежит кадр |
| Видео идёт, но курсор и клавиатура не работают | Сообщите разработчику: с одним каналом такого быть не должно — раньше это означало закрытые порты 7001-7002, теперь порт один |
| Соединение не устанавливается вовсе | При подключении **по ID** пробрасывать порты не нужно. Если не выходит — прислать вывод обеих сторон целиком: там видно, дошли ли встречные пакеты |
| `хост не в сети` | Хост не запущен, либо запущен с `--no-signaling`, либо ID введён неверно |
| `Неверный пароль` при верном пароле | Хост перезапускали: пароль новый при каждом запуске |
| `КЛЮЧ ЭТОЙ МАШИНЫ ИЗМЕНИЛСЯ` | Прислать снимок экрана. Либо у хоста переустановили систему, либо это подмена — программа намеренно не решает за человека |
| `хост не ответил на пароль` | Хост запущен с `--ask`, и за ним никто не нажал `y` |
| `хозяин машины отклонил подключение` | Ответили `n` на вопрос `--ask`. Не ошибка |

**Прямое соединение через NAT работает** — оба компьютера могут быть
за обычными домашними роутерами, пробрасывать порты не нужно.
Проверено между Москвой и Францией.

Исключение — «симметричный» NAT (чаще у мобильных операторов): там
прямое соединение невозможно в принципе, нужен промежуточный сервер,
которого пока нет. Ожидаемо это 15–20 % случаев.
