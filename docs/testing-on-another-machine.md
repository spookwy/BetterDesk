# Проверка на второй машине

Инструкция для второй стороны. Читать код не нужно.

Цель — узнать две вещи: запускается ли BetterDesk на машине, которую
разработчик не видел, и какая получается задержка через настоящий
интернет.

---

## Про две стороны — прочитать первым делом

Роли **не симметричны**, и это важно понимать до начала:

| Роль | Что делает | Что для этого нужно |
|---|---|---|
| **Клиент** | смотрит чужой экран | декодер (есть почти в любой Windows) |
| **Хост** | отдаёт свой экран | захват **и аппаратный энкодер** |

Видеокарта NVIDIA для роли хоста **не обязательна**: поддерживаются
NVENC (NVIDIA), Intel QuickSync и AMD — всё, что Windows считает
аппаратным энкодером H.264. Обычно это есть на любой машине не
старше десяти лет, включая ноутбуки со встроенной графикой.

Чего пока нет — софтверного кодирования. Машина совсем без
аппаратного энкодера хостом быть не сможет; клиентом — сможет.
Шаг 2 покажет, какой случай перед вами.

---

## Что понадобится

- Windows 10 (сборка 1903+) или Windows 11, 64 бита
- [Rust](https://rustup.rs/) — при установке выбрать вариант по
  умолчанию (MSVC)
- Visual Studio Build Tools с компонентом «Разработка классических
  приложений на C++»

Для роли **клиента** видеокарта NVIDIA не нужна вовсе.

---

## Шаг 1. Собрать

```powershell
cargo build --release -p bd-bench
```

Первая сборка занимает несколько минут. Если она падает — прислать
разработчику весь вывод целиком, дальше идти не нужно.

---

## Шаг 2. Проверить машину

**Это главный шаг.** Проба ничего не ломает и не требует соединения —
она только смотрит, что на машине есть:

```powershell
cargo run --release -p bd-bench --bin machine_probe
```

Вывод на машине без NVIDIA выглядит примерно так:

```
=== BetterDesk: проверка машины ===

✅ Захват экрана: DXGI Desktop Duplication работает, кодируется 1920x1080
     монитор 0: \\.\DISPLAY1 — 1920x1080
✅ Энкодер: Media Foundation: Intel® Quick Sync Video H.264 Encoder MFT
     (NVENC недоступен, и это нормально: ...)
✅ Декодер: H.264 D3D11VA готов (встроенный декодер Windows)

Энкодеры H.264, заявленные системой:
  • Intel® Quick Sync Video H.264 Encoder MFT — аппаратный
  • H264 Encoder MFT — софтверный

--- Вывод ---
✅ ХОСТ: машина может отдавать свой экран.
✅ КЛИЕНТ: машина может смотреть чужой экран.
```

**Прислать этот вывод целиком** — по нему видно всё нужное.

Как читать:

- **`✅ ХОСТ` и `✅ КЛИЕНТ`** — можно проверять в обе стороны.
- Строка «NVENC недоступен, и это нормально» — не ошибка: на машине
  без NVIDIA используется Intel или AMD, и это штатный путь.
- **`❌ ХОСТ`** — аппаратного энкодера нет вовсе либо ни один не
  подошёл. Клиентом машина при этом обычно остаётся годной.
- **`❌ КЛИЕНТ`** — дальше идти нельзя, нужен софтверный декодер,
  которого пока нет.

---

## Шаг 3. Подключиться

Тот, чей экран показывают (**хост**), запускает у себя:

```powershell
cargo run --release -p bd-bench --bin loopback -- --quic-host 0.0.0.0:7000 --seconds 120
```

Тот, кто смотрит (**клиент**), подключается — вместо `АДРЕС`
подставить внешний IP хоста:

```powershell
cargo run --release -p bd-bench --bin loopback -- --quic-connect АДРЕС:7000 --seconds 100
```

Хост ждёт подключения 60 секунд, клиент сдаётся через 15 — то есть
хост запускают первым.

Откроется окно с экраном хоста. **F9** показывает и прячет панель со
статистикой: задержка, fps, RTT, потери.

### Проверить в обе стороны

Это **два отдельных прогона**, а не один: одна сессия показывает
экран в одну сторону.

1. Первый прогон: хостом машина A, клиентом машина B.
2. Второй прогон: поменяться ролями — хостом B, клиентом A.

Второй прогон получится, если `machine_probe` на машине B сказал
`✅ ХОСТ`. Видеокарта NVIDIA для этого не нужна — годятся Intel
QuickSync и AMD.

---

## Что смотреть глазами

Цифры соберутся сами, а вот это увидит только человек:

1. **Картинка живая**, не замирает и не идёт рывками.
2. **Нет пикселизации** — картинка не грубеет крупными квадратами.
3. **Курсор** нормального размера, и над текстом видна буква «I»,
   а не квадрат и не пустое место.
4. **Ничего не падает** за всё время прогона.

Если что-то из этого не так — описать словами, что именно видно.
Это ценнее любых цифр: несколько дефектов подряд нашлись именно так,
и ни один из них не давал ни ошибки, ни неверного числа.

---

## Что прислать в конце

1. Вывод `machine_probe` целиком.
2. Последние ~40 строк вывода `loopback` (там итоговый отчёт).
3. Словами: как выглядело — плавно или рвано, что было не так.

Задержка через интернет будет заметно больше, чем в локальной сети,
и это ожидаемо: критерий проекта (≤ 35 мс) задан для LAN. Здесь
проверяется не он, а то, что всё вообще работает на другой машине.

---

## Если что-то пошло не так

Проба и `loopback` объясняют ошибки словами. Самые вероятные:

| Что видно | Что это значит |
|---|---|
| `Захват экрана недоступен` | Гибридная графика — известное ограничение DXGI, фоллбэк запланирован |
| `Аппаратный декодер H.264 недоступен` | Нужен софт-декодер, его пока нет |
| `NVENC недоступен` | Норма: используется Intel QuickSync или AMD |
| `ни один аппаратный энкодер не подошёл` | Гибридная графика: энкодер не видит GPU, которому принадлежит кадр |
| Соединение не устанавливается | Порт 7000 закрыт файрволом или NAT; пока нужен проброс порта |

Прямое соединение через NAT (без проброса порта) появится позже —
это отдельный этап работы.
