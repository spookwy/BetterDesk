# Облачная часть

Отдельный workspace: собирается под Linux и деплоится на VPS, тогда
как клиентский workspace прибит к Windows (`rust-toolchain.toml`).

| Что | Где |
|---|---|
| Сигналинг | `signaling/` — регистрация хостов по ID, сведение сторон |

---

## Запуск

```bash
cargo run --release -p bd-signaling -- --listen 0.0.0.0:9000
```

Проверка живости: `curl http://АДРЕС:9000/health` → `ok`.

## Живая проверка

Юнит-тесты проверяют разбор сообщений (они в `bd-core::signaling`).
Но **согласование сторон нельзя проверить, глядя на одну сторону** —
это урок находки 38, где ALPN у QUIC собирался с обеих сторон
по отдельности валидно, а вместе не работал.

Поэтому есть живая проверка: она поднимает два настоящих
WebSocket-соединения и проверяет весь путь.

```bash
# 1. Поднять сервер
cargo run -p bd-signaling -- --listen 127.0.0.1:9100

# 2. В другом окне
node signaling/tests/live_signaling.mjs
```

Проверяется одиннадцать вещей, среди них:

- хост регистрируется и получает **свой внешний адрес** — тот, что
  видит сервер, а не тот, что хост знает о себе;
- клиент по ID получает адрес хоста;
- **хост узнаёт о клиенте** — без встречного движения NAT не
  пробивается, и это самая частая причина «не соединяется»;
- когда обе стороны в одной сети, отдаются **локальные** адреса
  (домашние роутеры часто не разворачивают пакет обратно внутрь);
- несуществующий ID даёт **честную ошибку**, а не зависание;
- мусор в сокете не роняет сервер и не рвёт соединение;
- ушедший хост исчезает из реестра.

Проверка **проверена на способность провалиться**: с отключённой
отправкой `PeerWants` она падает с «таймаут ожидания: wants».

Зависимостей у неё нет: WebSocket встроен в Node 22+.

## Чего здесь пока нет

**Аутентификации.** Любой может назваться любым ID и забрать чужой
адрес. Это записанный временный компромисс до этапа 5, где появятся
ключи устройств (§7.3). До тех пор сигналингу верить нельзя, и это
прямо сказано в заголовке `main.rs`.

**Проверки подписки.** §8.3 требует, чтобы её делал сервер, а не
клиент — именно потому, что серверную проверку нельзя обойти патчем
бинарника. Появится вместе с аккаунтами.

**Деплоя.** Сервер пока запускается только локально. Oracle Cloud
Free — следующий шаг.
